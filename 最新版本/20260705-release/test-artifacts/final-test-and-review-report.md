## 已解决问题

1. 飞书旧 `docx blocks` 写入方式在并发和权限边界下会出现 `forBidden` / 429。
   处理：改为优先使用 `docs_ai` 文档追加接口，旧 block API 仅作为 fallback，并增加飞书短重试。

2. DeepSeek `deepseek-v4-pro` 在默认思考模式下可能返回空 `message.content`。
   处理：请求中加入 `thinking: { type: "disabled" }`，并把 LLM 请求改为轻量覆盖字段，减少超时和 token 浪费。

3. 大模型或飞书失败不能影响用户拿报告。
   处理：LLM 失败自动回退规则报告；飞书失败只记录集成状态，不阻断官网展示和 PDF 下载。

4. 公开页面不应暴露内部错误。
   处理：前端状态改成面向用户的“报告已生成/已进入跟进”，报告角标区分 `规则报告终版` 和 `DeepSeek 已优化终版`。

5. 移动端长表单一次性填写压力大。
   处理：诊断页改为分步问卷，移动端按钮、单选卡片、报告区和 PDF 下载均做适配。

## 5 轮架构与产品复盘

### 第 1 轮：数据可靠性

判断：没有数据库也可以支撑沙龙 MVP，但必须有持久化主链路。

优化：继续用 GitHub Issues 保存完整线索/报告作为主存储，飞书作为业务查看副本。这样飞书偶发失败不会丢数据，后续也能从 GitHub 补同步。

### 第 2 轮：报告生成性能

判断：50 人体量下，同步规则报告 + 可选 LLM 优化可接受；PDF 放前端生成是正确选择。

优化：LLM 加 25 秒超时和规则回退；PDF 在浏览器本地生成，服务器只负责结构化报告，避免服务端 PDF 渲染成为瓶颈。

### 第 3 轮：咨询转化

判断：报告不能只是打分，必须让企业主理解“为什么需要品牌管理”。

优化：报告加入组合诊断、客户感受、品牌管理洞察、建议服务路径、会后材料清单、咨询追问，方向从“做视觉/做内容”转为“管理客户理解、信任、选择和行动”。

### 第 4 轮：现场体验

判断：沙龙现场用户大概率用手机，填写必须轻、快、稳定。

优化：问卷拆成多步；按钮和选项卡扩大可点区域；移动端验证报告无横向溢出；内部集成错误不打扰用户。

### 第 5 轮：运维与上线

判断：上线前必须有可重复的公网测试，而不是手工点一遍。

优化：新增 `scripts/run-public-test-suite.mjs`，自动覆盖正式域名访问、API、移动端表单、PDF 下载、10 并发，并把 JSON / Markdown / 截图保存到 `test-artifacts/`。
